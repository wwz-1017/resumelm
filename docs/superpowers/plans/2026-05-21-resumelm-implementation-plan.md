# ResumeLM 实现计划

- 日期：2026-05-21
- 关联规格：[2026-05-21-resumelm-design.md](</Users/a1/Documents/ResumeLM 智能简历生成/docs/superpowers/specs/2026-05-21-resumelm-design.md>)
- 目标版本：匿名开放的 C 端第一版
- 周期：8-12 周

## 1. 实施目标

在 8-12 周内交付一个无需登录即可使用的中文简历生成与优化平台，覆盖以下核心链路：

- 新建简历
- 本地自动保存
- AI 生成与润色
- 个人评价与个人优势生成
- ATS 与 JD 匹配评分
- 模板预览
- PDF/Word/JSON 导出
- 点赞点踩与原因反馈
- BI 看板监控流量、转化、AI 使用和好评差评

## 2. 实施原则

1. 先打通主链路，再补增强能力。
2. 所有 AI 能力都走统一网关，避免页面直接耦合厂商。
3. 简历编辑、评分、导出使用同一份标准 JSON 模型。
4. 第一版优先匿名本地保存，不引入登录和云端草稿。
5. 反馈能力优先采用低成本结构化方案，先收集数据再做复杂分析。
6. BI 看板先做内部轻量分析，优先覆盖关键指标，不做复杂权限后台。

## 3. 里程碑拆分

### M1：工程与数据骨架

目标：建立可持续开发的工程基础，并完成匿名工作台最小闭环。

交付内容：

- `Next.js` 项目初始化
- 基础 UI 框架与页面路由
- 简历标准 JSON schema
- 本地持久化层 `IndexedDB/localStorage`
- 新建简历、导入 JSON、导出 JSON
- 匿名会话标识生成

验收标准：

- 打开首页可进入匿名工作台
- 用户刷新页面后可恢复草稿
- 用户可导入和导出标准 JSON

### M2：编辑器与模板预览

目标：让用户可以完整录入和编辑简历内容，并看到实时预览。

交付内容：

- 结构化编辑器
- 模块列表：基础信息、教育、实习、项目、校园经历、技能、奖项、个人评价、个人优势
- 拖拽排序或等价顺序调整能力
- 模板预览面板
- 基础模板 2-3 套
- 结构校验与缺失提示

验收标准：

- 用户能完成完整简历录入
- 模板切换可实时反映内容变化
- 空字段和结构错误可被识别

### M3：LLM Gateway 与 AI 生成能力

目标：把 AI 能力抽象成统一服务，并先交付最核心的生成与润色链路。

交付内容：

- `LLM Gateway` 模块
- 模型配置、路由、重试、错误映射
- Prompt 模板管理
- 基础信息生成整份简历初稿
- 分块润色工作经历与项目经历
- 个人评价与个人优势生成
- 技能关键词推荐

验收标准：

- 前端只调用内部 AI API，不直接调用模型厂商
- 生成结果能落到标准 JSON 中
- AI 失败时有明确错误提示和重试入口

### M4：评分引擎

目标：形成可解释、可落地的评分与建议输出。

交付内容：

- ATS 规则引擎
- JD 文本解析
- 关键词匹配分析
- LLM 评分与建议生成
- 评分结果结构化 JSON
- 评分报告 UI

验收标准：

- 用户输入 JD 后可获得总分与分项分
- 报告中可看到缺失关键词、问题项和建议
- 评分结果可重复渲染，不依赖模型原始文本格式

### M5：导出能力

目标：让用户能带走最终结果，形成完整闭环。

交付内容：

- 模板渲染中间层
- PDF 导出
- Word 导出
- 导出任务日志
- 导出失败处理与提示

验收标准：

- 导出的 PDF 不明显跑版
- Word 文档具备基础可编辑性
- 同一份简历在多个模板下可稳定导出

### M6：反馈模块、BI 看板与质量收口

目标：收集用户对结果质量的判断，建立产品关键指标看板，并完成首版上线前的稳定性优化。

交付内容：

- AI 结果点赞/点踩
- 评分结果点赞/点踩
- 原因标签选择
- 自由文本建议
- `product_feedback` 数据落库
- 关键行为事件采集
- BI 看板基础页面
- 流量、转化、AI 使用、导出和反馈指标
- 频率限制、日志、基础监控
- 错误页和加载态打磨

验收标准：

- 用户可以对关键结果提交反馈
- 后端可以区分反馈对象、反馈类型和原因
- 内部看板可以查看访问量、核心漏斗、点赞点踩和差评原因排行
- 核心链路具备基本错误监控能力

## 4. 模块拆解

### 4.1 前端模块

- `landing`：产品入口页
- `workspace`：匿名工作台
- `editor`：结构化简历编辑器
- `preview`：模板预览区
- `scoring`：评分报告页
- `feedback`：结果反馈组件
- `export`：导出状态与结果提示
- `analytics-dashboard`：内部 BI 看板

### 4.2 后端模块

- `ai-gateway`：统一 AI 调用层
- `resume-schema`：简历 JSON schema 与校验
- `scoring-engine`：规则评分与 LLM 评分组合器
- `export-service`：PDF/Word 导出服务
- `feedback-service`：反馈写入与标签管理
- `analytics-service`：关键事件采集与指标聚合
- `observability`：日志与监控

### 4.3 数据存储模块

- 浏览器本地存储：草稿、模板选择、最近导出状态
- Supabase：事件日志、任务日志、评分报告缓存、反馈记录、指标快照

## 6. 任务顺序与依赖

1. 先完成 `resume-schema`，因为编辑器、AI、评分、导出都依赖它。
2. 再完成本地存储和匿名工作台，保证最小可用产品尽快跑通。
3. 然后实现编辑器和模板预览，形成可见可编辑的主界面。
4. 接着接入 `LLM Gateway`，避免生成能力后期返工。
5. 评分引擎在 AI 初版后接入，因为它依赖标准化简历结构和 JD 解析。
6. 导出能力放在评分后，但模板渲染层要更早设计，避免预览和导出两套系统。
7. 反馈模块和 BI 看板最后接入，但前期就要在事件埋点、数据表和页面留好挂点。

## 7. 数据表计划

### 第一批

- `anonymous_sessions`
- `analytics_events`
- `ai_requests`
- `score_reports`

### 第二批

- `export_tasks`
- `product_feedback`
- `feedback_tags`
- `daily_metric_snapshots`

### BI 指标口径

- 流量：按匿名会话与页面访问事件统计。
- 转化：按 `workspace_entered`、`resume_created`、`ai_generated`、`score_completed`、`export_completed` 事件统计。
- AI 使用：按 `ai_requests` 的任务类型、耗时、失败状态统计。
- 反馈：按 `product_feedback` 的 `vote`、原因标签和对象类型统计。
- 导出：按 `export_tasks` 的文件类型、成功状态和失败原因统计。

## 8. 测试计划

### 单元测试

- 简历 schema 校验
- 本地存储读写
- 评分规则函数
- AI 响应解析函数
- 反馈原因映射逻辑
- BI 指标聚合函数

### 集成测试

- 从输入基础信息到生成简历初稿
- 从粘贴 JD 到获得评分报告
- 从编辑模板到导出 PDF/Word
- 从结果页提交反馈到数据库记录
- 从行为事件到 BI 指标聚合展示

### 手工验证

- 桌面端常见分辨率下的编辑与预览体验
- 长简历与短简历在多模板下的导出效果
- AI 失败、超时、空结果等异常流程

## 9. 风险控制

### 导出质量风险

方案：尽早确定模板渲染中间层，预览与导出共用一套结构。

### AI 输出漂移风险

方案：所有关键输出使用 schema 校验与后处理，必要时回退到局部生成。

### 匿名模式数据丢失风险

方案：强化自动保存提示，并在显著位置提供 JSON 导出备份。

### 反馈噪音风险

方案：优先使用预设标签而不是纯自由文本，降低无效数据比例。

### BI 指标失真风险

方案：统一事件命名和触发时机，避免同一用户动作被重复统计。

## 10. 首个开发切片

第一轮实现建议只做下面这条最小主链路：

1. 首页进入匿名工作台
2. 创建简历草稿
3. 编辑基础信息和教育经历
4. 自动本地保存
5. JSON 导出
6. 单模板预览
7. 预留匿名会话 ID 和关键事件采集接口

完成这一切片后，再叠加 AI、评分和导出服务。这样可以最快验证数据结构和交互骨架是否正确。

## 11. 完成定义

当以下条件全部满足时，可认为第一版具备上线条件：

- 匿名用户无需登录即可完成主链路
- 核心 AI 功能稳定可用
- 评分报告结构化且可解释
- PDF/Word 导出达到可投递标准
- 反馈模块可持续采集有效数据
- BI 看板可查看关键流量、转化和好评差评指标
- 核心异常有日志和基础监控
