# ResumeLM 简历解析准确度提升方案

> 适用产品：ResumeLM — AI 智能简历生成与优化平台  
> 目标：提升用户上传 PDF / Word 简历后的自动结构化解析准确度  
> 重点方向：版式感知、多段切分、章节模糊识别、字段置信度、AI 兜底解析、用户确认页

---

## 1. 背景与当前问题

当前产品已经支持用户上传 PDF、DOCX、DOC、JSON 等格式简历，并通过 `pdfjs-dist / mammoth` 提取纯文本后进行结构化解析。

现有流程大致如下：

```text
PDF / DOCX 文件
  ↓
pdfjs-dist / mammoth 提取纯文本
  ↓
文本预处理：合并多余空格、统一换行符
  ↓
逐行扫描，正则匹配章节标题
  ↓
切分为 personalSummary / education / internships / projects / campusExperience / skills / awards / strengths / general
  ↓
各模块独立解析
  ↓
组装为 ResumeDocument JSON
```

当前基础解析已经可用，但主要存在以下问题：

1. 章节标题识别依赖固定正则，非标准标题容易漏识别。
2. 实习、项目、校园经历等模块容易被合并成一条记录。
3. 教育经历只能解析一条，多学位场景支持不足。
4. PDF 纯文本提取会丢失版式信息，多栏简历容易顺序混乱。
5. 企业名称识别依赖后缀，无法识别“腾讯”“字节跳动”等无后缀公司名。
6. 技能模块容易受到正文长句干扰。
7. 解析结果没有字段置信度，用户无法知道哪些内容可能解析错误。
8. AI 兜底解析尚未真正接入。

---

## 2. 总体优化方向

建议将当前“纯规则解析”升级为“规则引擎 + 版式理解 + 置信度评分 + AI 兜底”的混合解析架构。

推荐流程：

```text
PDF / DOCX / DOC
  ↓
版式块提取：LineBlock[]
  ↓
文本清洗 + 行合并 + 分栏重排
  ↓
章节识别：标题规则 + 模糊匹配 + 版式特征打分
  ↓
模块内容切分：education / work / project / campus / skills / awards ...
  ↓
模块内多段拆分：按日期、组织、职位、分隔符、空行综合判断
  ↓
字段抽取：规则优先
  ↓
字段置信度评分
  ↓
低置信度字段调用 AI 兜底
  ↓
用户确认页修正
  ↓
ResumeDocument JSON
```

这套架构的核心原则是：

- 规则解析负责高频、稳定、低成本场景。
- 版式信息负责解决 PDF 多栏、侧边栏、标题样式等问题。
- 置信度负责判断哪些字段可靠、哪些字段需要复核。
- AI 只处理低置信度或结构复杂的局部内容，避免全量调用带来的成本和不稳定性。
- 解析确认页负责把不可避免的不确定性显性化，让用户快速修正。

## 3. 第一优先级：引入 LineBlock 版式结构

当前如果只保存纯文本行，会丢失 PDF 中的坐标、字体、加粗、分栏信息。建议将解析中间层升级为 `LineBlock[]`。

### 3.1 推荐数据结构

```ts
type LineBlock = {
  text: string
  page: number
  x: number
  y: number
  width: number
  height: number
  fontSize?: number
  fontWeight?: number
  isBold?: boolean
  source: 'pdf' | 'docx'
}
```

### 3.2 PDF 分栏重排逻辑

不要简单按 `y` 从上到下拼接文本。建议按页面、列、坐标综合排序。

```ts
function reorderPdfLines(blocks: LineBlock[]) {
  // 1. 按 page 分组
  // 2. 每页内根据 x 聚类，判断是否存在左栏 / 右栏
  // 3. 如果存在明显双栏，先识别侧栏和主栏
  // 4. 每栏内按 y 升序、x 升序排序
  // 5. 最终生成更符合人类阅读顺序的 LineBlock[]
}
```

### 3.3 双栏判断规则

```ts
const pageWidth = maxX - minX

const leftBlocks = blocks.filter(b => b.x < pageWidth * 0.35)
const rightBlocks = blocks.filter(b => b.x > pageWidth * 0.35)

const isTwoColumn =
  leftBlocks.length > 8 &&
  rightBlocks.length > 8 &&
  medianWidth(leftBlocks) < medianWidth(rightBlocks) * 0.8
```

### 3.4 侧栏识别建议

很多校招简历左侧是侧栏，通常包含：

- 联系方式
- 技能
- 证书
- 荣誉
- 语言能力
- 兴趣爱好

右侧通常包含：

- 教育经历
- 实习经历
- 项目经历
- 校园经历

解析时可以优先把左侧短文本归入候选技能、证书、个人信息区域，避免与右侧经历正文混淆。

## 4. 章节识别：从正则匹配升级为分类打分

当前章节识别主要依赖精确关键词，例如“教育经历”“教育背景”“教育”。但真实简历中会出现很多变体，比如：

- 教育情况
- 学习背景
- 学历信息
- 职业背景
- 项目展示
- 个人亮点
- 核心竞争力

建议将章节识别从“命中某个正则”升级为“章节分类打分”。

### 4.1 推荐章节别名词库

```ts
const SECTION_ALIASES = {

  projects: [
```

### 4.2 标题判断逻辑

```ts
function isLikelySectionTitle(line: LineBlock): boolean {
  const text = clean(line.text)

  return (
    text.length <= 16 &&
    !hasDate(text) &&
    !hasEmail(text) &&
    !hasPhone(text) &&
    (
      line.isBold ||
      line.fontSize >= avgFontSize * 1.1 ||
      /^[一二三四五六七八九十、\d. ]*(.+)$/.test(text)
    )
  )
}
```

### 4.3 章节分类打分

```text
sectionScore =
  标题关键词相似度
+ 标题版式特征
+ 行长度特征
+ 上下文特征
+ 页面位置特征
```

例如：

```json
{
  "section": "education",
  "title": "学习背景",
  "confidence": 0.86,
  "reason": ["alias_match:学习背景", "short_line", "bold"]
}
```

### 4.4 章节识别输出结构

```ts
type SectionDetection = {
  section: ResumeSection
  title: string
  confidence: number
  reason: string[]
  startLineIndex: number
  endLineIndex: number
}
```

## 5. 经历多段拆分：用边界打分替代整段合并

当前问题是：实习经历、项目经历、校园经历等章节容易被整体合并成一条记录。

例如：

```text
腾讯 产品实习生 2023.06-2023.09
- 负责用户调研...
- 推动需求上线...

字节跳动 运营实习生 2023.10-2024.01
- 搭建内容看板...
- 提升转化率...
```

现有逻辑可能会把上面内容解析成一条经历。正确结果应该是两条。

### 5.1 新经历边界信号

一行可能是新经历开头，如果满足以下特征：

1. 包含日期范围。
2. 包含组织名。
3. 包含职位名。
4. 行较短，不像描述正文。
5. 上一行为空行或有明显间隔。
6. 当前行加粗或字号较大。
7. 当前行不是 bullet 描述。

### 5.2 边界判断函数

```ts
function isNewExperienceStart(line: LineBlock, prev?: LineBlock): boolean {
  let score = 0
  const text = line.text

  if (hasDateRange(text)) score += 3
  if (hasOrganization(text)) score += 2
  if (hasRole(text)) score += 2
  if (text.length <= 40) score += 1
  if (line.isBold) score += 1
  if (prev && isBlankGap(prev, line)) score += 1

  if (startsWithBullet(text)) score -= 3
  if (looksLikeDescription(text)) score -= 2

  return score >= 4
}
```

### 5.3 经历块结构

```ts
type ExperienceBlock = {
  headerLines: LineBlock[]
  bulletLines: LineBlock[]
  rawText: string
  confidence: number
}
```

### 5.4 通用拆分函数

```ts
function splitEntriesByBoundary(lines: LineBlock[], type: SectionType) {
  const entries: LineBlock[][] = []
  let current: LineBlock[] = []

  for (const line of lines) {
    const isStart =
      type === 'education'
        ? isNewEducationStart(line.text)
        : isNewExperienceStart(line, current[current.length - 1])

    if (isStart && current.length > 0) {
      entries.push(current)
      current = [line]
    } else {
      current.push(line)
    }
  }

  if (current.length > 0) entries.push(current)

  return entries
}
```

## 6. 教育经历：支持多学位和多段教育

教育经历不应只解析一条。真实简历中常见：

- 本科 + 硕士
- 本科 + 交换经历
- 本科 + 双学位
- 国内学校 + 海外学校
- 学校 + 培训项目

### 6.1 教育新段判断

```ts
function isNewEducationStart(line: string): boolean {
  return (
    hasDateRange(line) ||
    hasSchoolName(line) ||
    /(本科|硕士|研究生|博士|大专|MBA)/.test(line)
  )
}
```

### 6.2 学校识别增强

原规则：

```regex
/[\u4e00-\u9fa5]+(?:大学|学院|学校)/
```

建议扩展为：

```regex
/[\u4e00-\u9fa5A-Za-z·\s]+(?:大学|学院|学校|研究院|University|College|Institute)/
```

### 6.3 推荐教育字段结构

```ts
type Education = {
  school: string
  degree: string
  major: string
  startDate?: string
  endDate?: string
  gpa?: string
  ranking?: string
  courses?: string[]
  rawText: string
  confidence: number
}
```

### 6.4 可额外解析的教育信息

```text
GPA: 3.8/4.0
排名：前10%
主修课程：数据结构、数据库、机器学习
荣誉：一等奖学金、优秀毕业生
```

这些信息可以用于后续 ATS 评分和 AI 润色。

## 7. 企业组织名识别增强

当前组织识别依赖“公司”“集团”“科技”等后缀，导致“腾讯”“字节跳动”“美团”等无后缀组织名漏识别。

建议三层识别。

### 7.1 第一层：后缀规则

```ts
const ORG_SUFFIX = [
  '公司', '集团', '科技', '网络', '信息', '咨询', '银行',
  '证券', '基金', '实验室', '研究院', '工作室', '团队',
  '部门', '中心', '事业部'
]
```

### 7.2 第二层：常见企业词库

```ts
const ORG_DICTIONARY = [
  '腾讯', '阿里巴巴', '字节跳动', '美团', '京东', '百度',
  '网易', '小红书', '拼多多', '快手', '蚂蚁集团',
  '华为', '小米', '滴滴', '携程', '哔哩哔哩',
  '微软', '谷歌', '亚马逊', 'Meta', 'Apple'
]
```

### 7.3 第三层：上下文模式

组织名通常出现在：

- 日期附近
- 职位名前后
- 行首
- “组织 + 职位 + 日期”结构中
- “组织 | 职位 | 日期”结构中

例如：

```text
腾讯 | 产品实习生 | 2023.06-2023.09
```

可解析为：

```json
{
  "organization": "腾讯",
  "role": "产品实习生",
  "startDate": "2023-06",
  "endDate": "2023-09"
}
```

如果组织名置信度低，再交给 AI 兜底。

## 8. 技能解析优化

当前技能解析通过顿号、逗号、分号、竖线拆分数组。该方法简单有效，但容易把正文长句误拆成技能。

### 8.1 技能解析限制

建议增加三个限制：

1. 优先只在 `skills` 章节内解析。
2. 对 PDF 左侧短文本区域进行技能候选识别。
3. 候选词必须符合技能词形或命中技能词库。

### 8.2 技能候选过滤函数

```ts
function isSkillCandidate(token: string): boolean {
  return (
    token.length >= 2 &&
    token.length <= 30 &&
    !hasDate(token) &&
    !hasPhone(token) &&
    !looksLikeSentence(token) &&
    (
      inSkillDictionary(token) ||
      /Python|Java|SQL|Excel|Figma|Axure|SPSS|Tableau|PowerBI|React|Vue|Node/i.test(token) ||
      /数据分析|用户研究|竞品分析|需求分析|项目管理|产品设计/.test(token)
    )
  )
}
```

### 8.3 技能分类结构

不建议只存字符串数组，建议按类别存储：

```ts
type SkillGroup = {
  category: 'language' | 'tool' | 'technical' | 'business' | 'certificate' | 'other'
  items: string[]
}
```

示例：

```json
[
  { "category": "tool", "items": ["Figma", "Axure", "Excel"] },
  { "category": "business", "items": ["用户研究", "竞品分析", "需求分析"] },
  { "category": "language", "items": ["英语六级"] }
]
```

这样后续 ATS 评分和 JD 关键词匹配会更准确。

## 9. 个人评价与个人优势解析优化

当前逻辑是合并 `personalSummary` 和 `strengths`，然后：

- 大于等于 15 字符的行作为个人评价；
- 2 到 25 字符的行作为个人优势；
- 个人评价截断到 100 字。

这套逻辑容易误判，也可能截断有效信息。

### 9.1 个人评价不要过早截断

建议将个人评价上限从 100 字提升到 300 字，或者保留原文。

```ts
personalSummary: {
  text: normalizedSummary.slice(0, 300),
  rawText: normalizedSummary
}
```

### 9.2 优势条目识别 bullet

```ts
function isStrengthLine(line: string): boolean {
  return (
    startsWithBullet(line) ||
    /^(优势|亮点|能力|特点)\d?[:：]/.test(line) ||
    /(沟通|学习|抗压|执行|逻辑|分析|协作|责任心|主动性)/.test(line)
  )
}
```

### 9.3 示例

输入：

```text
个人优势：
- 数据敏感，熟悉 SQL 和 Excel
- 沟通能力强，有跨部门协作经验
- 逻辑清晰，能独立完成需求分析
```

输出：

```json
{
  "personalSummary": "",
  "strengths": [
    "数据敏感，熟悉 SQL 和 Excel",
    "沟通能力强，有跨部门协作经验",
    "逻辑清晰，能独立完成需求分析"
  ]
}
```

## 10. 日期解析标准化

日期解析是经历拆分、教育拆分、字段置信度的重要基础。

### 10.1 需要支持的日期格式

```text
2023.06-2023.09
2023/06 - 2023/09
2023年6月 - 2023年9月
2023.06 至今
2023.06 - Present
2023-06 ~ 2023-09
2023.6—2023.9
```

### 10.2 推荐正则

```ts
const DATE_RANGE_REGEX =
/(?<startYear>20\d{2}|19\d{2})[.\-/年\s]*(?<startMonth>0?[1-9]|1[0-2])?\s*(?:月)?\s*[-—–~至到]\s*(?<end>(?:20\d{2}|19\d{2})[.\-/年\s]*(?:0?[1-9]|1[0-2])?|至今|现在|Present|Now)/i
```

### 10.3 标准化输出

```json
{
  "startDate": "2023-06",
  "endDate": "2023-09",
  "isCurrent": false
}
```

## 11. 字段置信度设计

解析系统不应“静默填错”。建议所有关键字段都带置信度、来源和证据。

### 11.1 字段结构

```ts
type ParsedField<T> = {
  value: T
  confidence: number
  source: 'regex' | 'section_rule' | 'layout' | 'dictionary' | 'ai' | 'user'
  evidence: string
}
```

### 11.2 示例

```json
{
  "organization": {
    "value": "腾讯",
    "confidence": 0.82,
    "source": "dictionary",
    "evidence": "腾讯 产品实习生 2023.06-2023.09"
  }
}
```

### 11.3 需要触发 AI 兜底的情况

```ts
const NEED_AI_FALLBACK =
  field.confidence < 0.65 ||
  section.confidence < 0.7 ||
  experienceBlocks.length === 1 && hasMultipleDateRanges(rawText) ||
  hasConflict(parsedResult)
```

重点触发场景：

1. `general` 段落内容过多。
2. 一个经历章节中检测到多个日期范围，但只解析出一条经历。
3. 教育章节中出现多个学校或多个日期，但只解析出一条教育经历。
4. 组织名为空，但职位和日期存在。
5. 技能数量异常少或异常多。
6. PDF 检测到双栏，但文本顺序可能混乱。
7. 章节标题识别置信度较低。
8. 同一行被多个模块同时命中。

## 12. AI 兜底解析策略

AI 不建议每次整份简历都调用。更推荐“局部兜底”。

### 12.1 调用策略

```text
规则解析成功且置信度高：不调用 AI
规则解析部分失败：只把失败模块发给 AI
规则解析明显混乱：整份发给 AI
```

### 12.2 AI 输入结构

```json
{
  "task": "extract_resume_fields",
  "targetSections": ["internships", "projects"],
  "rawText": "...",
  "ruleParsedResult": {},
  "lowConfidenceFields": [
    "internships[0].organization",
    "projects"
  ],
  "schema": "ResumeDocument"
}
```

### 12.3 AI Prompt 建议

```text
你是简历结构化解析器。
请只输出合法 JSON，不要输出解释。
不要编造不存在的信息。
如果字段无法确定，返回空字符串，并设置 confidence < 0.5。
保留原文证据 evidence。
经历必须按时间或版面顺序拆分为多条。
```

### 12.4 AI 输出格式

```json
{
  "internships": [
    {
      "organization": "腾讯",
      "role": "产品实习生",
      "startDate": "2023-06",
      "endDate": "2023-09",
      "description": [
```

## 13. 解析确认页设计

建议不要直接让用户进入工作台，而是先进入“解析确认页”。

### 13.1 页面展示内容

解析确认页建议展示：

1. 已识别模块。
2. 每个模块解析条数。
3. 低置信度字段标黄。
4. 未识别内容归入“待确认内容”。
5. 用户可以拖拽未识别内容到正确模块。
6. 用户可以合并、拆分、删除经历条目。
7. 用户确认后再进入工作台。

### 13.2 示例展示

```text
教育经历：2 条，高置信度
实习经历：3 条，1 个字段待确认
项目经历：1 条，高置信度
技能：12 个，2 个疑似误识别
未分类内容：4 行
```

### 13.3 用户修正反哺

用户在确认页的修正可以记录为训练数据或规则优化依据：

```ts
type UserCorrection = {
  originalText: string
  oldSection: string
  newSection: string
  oldField?: string
  newField?: string
  action: 'move' | 'edit' | 'split' | 'merge' | 'delete'
}
```

长期来看，这些修正数据可以用于：

- 优化章节别名词库；
- 优化边界切分规则；
- 评估 AI 兜底效果；
- 形成真实解析评测集。

## 14. 推荐开发优先级

### 14.1 P0：最快提升准确率

1. 经历多段拆分  
   按日期、组织、职位、空行、分隔符做边界打分。

2. 教育多段拆分  
   支持本科 + 硕士 + 交换经历。

3. 章节标题模糊匹配  
   加别名词库和标题置信度。

4. 字段置信度  
   每个字段保留 `confidence`、`source`、`evidence`。

5. AI 局部兜底  
   只处理低置信度字段。

### 14.2 P1：解决复杂 PDF

1. PDF 坐标分栏。
2. 侧栏识别。
3. 表格 / 两列内容重排。
4. 字体大小和加粗辅助标题识别。

### 14.3 P2：长期准确率提升

1. 企业、学校、技能词库。
2. 用户修正反哺。
3. 简历模板版式识别。
4. 解析评测集。
5. AB 测试不同解析策略。

## 15. 解析质量评估指标

为了判断准确度是否真正提升，建议建立一套匿名简历测试集，至少包含 50 到 100 份不同模板的简历。

### 15.1 推荐指标

```ts
type ParseEvaluation = {
  sectionAccuracy: number      // 章节识别准确率
  entrySplitAccuracy: number   // 经历条目拆分准确率
  fieldAccuracy: number        // 字段抽取准确率
  skillPrecision: number       // 技能解析精确率
  skillRecall: number          // 技能解析召回率
  educationAccuracy: number
  organizationAccuracy: number
}
```

### 15.2 回归测试重点

每次修改解析规则后，需要重点检查：

1. 是否把多段经历正确拆开。
2. 是否把技能误放进项目。
3. 是否把项目描述误识别成奖项。
4. 是否漏掉学校、公司、岗位、时间。
5. `general` 段落剩余内容是否减少。
6. 低置信度字段是否准确标记。
7. AI 兜底是否只在必要时触发。
8. 用户确认页是否能快速纠错。

## 16. 推荐核心代码流程

建议将主流程组织为：

```ts
parseResume(file)
  -> extractLayoutBlocks(file)
  -> normalizeBlocks(blocks)
  -> detectSections(blocks)
  -> splitEntriesByBoundary(sectionBlocks)
  -> extractFieldsWithConfidence(entries)
  -> aiFallbackForLowConfidence(result)
  -> buildResumeDocument(result)
```

### 16.1 AI 兜底判断函数

```ts
function shouldUseAiFallback(result: ResumeDocument) {
  return (
    result.meta.lowConfidenceFields.length > 0 ||
    result.meta.unclassifiedLines.length > 5 ||
    result.meta.hasMultipleDateRangesButSingleEntry ||
    result.meta.layoutWarning === 'possible_two_column_mixed'
  )
}
```

### 16.2 推荐 ResumeDocument 元信息

```ts
type ResumeParseMeta = {
  parserVersion: string
  sourceType: 'pdf' | 'docx' | 'doc' | 'json'
  sectionConfidence: Record<string, number>
  lowConfidenceFields: string[]
  unclassifiedLines: string[]
  layoutWarning?: string
  aiFallbackUsed: boolean
  parseWarnings: string[]
}
```

## 17. 最终建议

当前解析器已经具备基础能力，但准确度瓶颈不是单个正则，而是整体策略还停留在：

```text
纯文本顺序 + 标题正则 + 单段抽取
```

建议尽快升级为：

```text
版式感知 + 章节分类打分 + 多段边界切分 + 字段置信度 + AI 局部兜底 + 用户确认页
```

最优先落地的五件事是：

1. 实习 / 项目 / 校园经历多段拆分。
2. 教育经历多段拆分。
3. 章节标题模糊匹配和别名词库。
4. 字段置信度与低置信度提示。
5. AI 局部兜底解析。

这几项完成后，ResumeLM 在校招简历、多栏模板、多段实习、多项目经历、多教育背景等场景下的解析准确度会明显提升。
