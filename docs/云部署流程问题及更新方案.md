## 二、部署流程

### 2.1 首次部署

```bash
# 1. 进入项目目录
cd '/Users/a1/Documents/ResumeLM 智能简历生成'

# 2. 安装 Cloudflare 相关依赖（已完成）
npm install -D @opennextjs/cloudflare wrangler --legacy-peer-deps

# 3. 登录 Cloudflare
npx wrangler login

# 4. 构建并部署
npm run pages:build && npx wrangler deploy --commit-dirty=true
```

### 2.2 配置环境变量

```bash
npx wrangler secret put AI_GATEWAY_BASE_URL   # https://api.deepseek.com/v1
npx wrangler secret put AI_GATEWAY_API_KEY     # 你的 API Key
npx wrangler secret put AI_GATEWAY_MODEL       # deepseek-chat
```

### 2.3 后续更新

每次修改代码后：

```bash
cd '/Users/a1/Documents/ResumeLM 智能简历生成'
npm run pages:build && npx wrangler deploy --commit-dirty=true
```

## 三、关键配置文件

### wrangler.toml

```toml
name = "resumelm"
main = ".open-next/worker.js"
compatibility_date = "2025-05-29"
compatibility_flags = ["nodejs_compat"]

[assets]
directory = ".open-next/assets"
binding = "ASSETS"
```

### open-next.config.ts

```ts
import { defineCloudflareConfig } from "@opennextjs/cloudflare/config";
export default defineCloudflareConfig({});
```

### package.json 脚本

```json
"pages:build": "npx opennextjs-cloudflare build && cp .open-next/worker.js .open-next/_worker.js",
"pages:deploy": "npx wrangler deploy"
```

## 四、遇到的问题及解决方案

### 问题 1：子模块克隆失败

**报错**：`No url found for submodule path 'andrej-karpathy-skills'`

**原因**：仓库中存在一个没有 URL 的损坏 Git 子模块，Cloudflare Pages 无法拉取。

**解决**：
```bash
git rm --cached andrej-karpathy-skills
rm -rf andrej-karpathy-skills
```

---

### 问题 2：Next.js 16 不兼容 @cloudflare/next-on-pages

**报错**：`peer next@">=14.3.0 && <=15.5.2" from @cloudflare/next-on-pages`

**原因**：`@cloudflare/next-on-pages` 最高支持 Next.js 15，项目使用 Next.js 16。

**解决**：换成 `@opennextjs/cloudflare`（Cloudflare 原生适配器，支持 Next.js 16）：
```bash
npm uninstall @cloudflare/next-on-pages
npm install -D @opennextjs/cloudflare --legacy-peer-deps
```

---

### 问题 3：缺 open-next.config.ts

**报错**：`No open-next.config.ts file was found in the project root`

**解决**：创建 `/open-next.config.ts`：
```ts
import { defineCloudflareConfig } from "@opennextjs/cloudflare/config";
export default defineCloudflareConfig({});
```

---

### 问题 4：Git 集成部署后静态资源 404

**现象**：Cloudflare Pages 通过 Git 集成部署成功，但网页只有文字，CSS/JS 全部 404。

**原因**：`wrangler pages deploy .open-next` 部署的 `_worker.js` 虽然能处理动态请求，但静态资源（CSS/JS/图片）没有被正确上传或路由。

**解决**：放弃 Pages Git 集成，改用 Worker + Assets 模式部署：
- `wrangler.toml` 配置 `[assets]` 绑定 `.open-next/assets`
- 使用 `wrangler deploy` 而非 `pages deploy`

---

### 问题 5：API Key 泄露到 GitHub

**报错**：GitHub 安全扫描检测到仓库中含有 API Key。

**原因**：`src/features/workspace/resume-workspace.tsx` 中 `aiConfig` 默认值写死了真实 Key。

**解决**：
1. 将默认值改为空字符串
2. `git commit --amend` 重写历史
3. `git push --force` 覆盖远程
4. 在 DeepSeek 后台重新生成新 Key

**教训**：永远不要在源代码中硬编码 API Key。环境变量和 Secret 用 `wrangler secret put` 管理。

---

### 问题 6：wrangler login 在非交互环境无法使用

**报错**：`In a non-interactive environment, it's necessary to set a CLOUDFLARE_API_TOKEN`

**解决**：在 Mac 终端（非 Claude Code 内）运行 `npx wrangler login`，完成后凭证会保存在本地，后续所有 wrangler 命令自动使用。

## 五、部署架构

```
本地代码
    │
    ├── npm run pages:build
    │     ├── next build (Next.js 构建)
    │     └── opennextjs-cloudflare build (生成 Worker 包)
    │           └── .open-next/
    │                 ├── worker.js (入口)
    │                 ├── assets/ (静态资源)
    │                 ├── middleware/ (中间件)
    │                 └── server-functions/ (服务端函数)
    │
    └── npx wrangler deploy
          ├── 上传 worker.js → Cloudflare Workers
          └── 上传 assets/ → Cloudflare Assets
                │
                ▼
          https://resumelm.wwz7300.workers.dev
```

## 六、注意事项

1. **不要用 Git 集成自动部署**：当前架构使用 `wrangler deploy` 手动部署，不依赖 Cloudflare Pages Git 集成
2. **API Key 管理**：用 `npx wrangler secret put` 设置，不要写在代码或 `.env` 里提交到 Git
3. **每次更新后手动部署**：修改代码 → `npm run pages:build && npx wrangler deploy --commit-dirty=true`
4. **`.open-next` 目录**：构建产物，已在 `.gitignore` 中排除，不要提交
5. **wrangler.toml**：已提交，包含 Worker 配置和静态资源绑定
